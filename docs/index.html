Act I — Why it collapses

The reported metrics were never produced by auditable code

This isn't a claim about a single bad line. Inspecting the original strategy scripts settled the cause: they contain no profit-and-loss logic at all. They emit a signal column and hand it to an external, closed-source scorer whose execution conventions can't be inspected.

Original — delegated to a black box

No P&L code exists to audit. Fill timing, fee model, and drawdown definition all live inside a proprietary SDK. A Sharpe of ~6 came out; how, is unverifiable.

# the only "backtest" behind the reported numbers
client = Client()
result = client.backtest(
    file_path=csv_path, ...   # opaque
)

Rebuild — execution you can read

A signal observed at bar t fills at bar t+1's open — never at t's close. Enforced by an invariant and a dedicated unit test. Run the identical signals here and the edge vanishes.

# src/backtester.py — auditable, tested
exec_price = prices_open[t + 1]
# test_no_lookahead asserts this

An independent from-scratch reconstruction — a different codebase built only from the strategy's written design — landed at a Sharpe of −0.54 on the same data. Two independent auditable implementations agree the true edge is near zero; only the black-box scorer produced ~6.

Act II — The framework

The strategies are ordinary. The validation is the contribution.

The driving question is never "can I get a high Sharpe?" — that's the easy part. It's "how do we know a high Sharpe is real edge rather than lookahead, overfitting, or selection?" Answering it takes infrastructure the prototype didn't have.

01

No-lookahead backtester

In-house, deterministic, next-bar-open execution. Every fill auditable line by line, with a test that fails if timing slips.

02

Walk-forward validation

Rolling and expanding windows with purging and embargo, producing many disjoint out-of-sample folds from one dataset.

03

Deflated Sharpe Ratio

Bailey & López de Prado (2014): corrects the in-sample Sharpe for trial count, sample size, and return non-normality.

04

Stationary bootstrap CIs

Politis–Romano bootstrap that respects the serial correlation of trade returns — a point estimate becomes a robustness claim.

05

RL-vs-rule baselines

Tests whether the tabular Q-learning agent actually adds signal over hand-coded rules on the same features, across seeds.

06

Ablations & cold OOS

Every design choice ablated; a frozen-parameter runner for data the strategies have never seen. No hidden knobs.

What this demonstrates

Aggregate metrics will always tell you a strategy works. Validation infrastructure tells you whether to believe them. This project is that thesis shown end-to-end on real data: a reported Sharpe near 6, driven to a corrected edge of zero under honest scrutiny.

  • As tradeable alpha: negative — no genuine risk-adjusted edge, large real drawdowns.
  • As a validation result: the framework caught an inflated backtest, which is exactly what it was built to do.
  • The cause is stated as far as the evidence allows — unverifiable external execution, not an invented bug.
